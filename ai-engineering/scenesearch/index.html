SceneSearch

Multimodal video retrieval with reproducible evaluation.

An AI-engineering project that searches a video library using natural language and returns timestamped moments supported by transcript and visual evidence.

Planned. Nothing is built. Every measurement on this page reads "not yet measured" because no experiment has run. No repository or demo exists yet. Links appear here when there is something real to point at.

Repository coming soon Demo planned

Overview

Problem and scope
The problem
Editors, creators and researchers need to find a specific moment in a video library without watching everything. Transcript search alone misses what is shown rather than said, and browsing by eye does not scale past a few hours of footage.
The approach
Index a small video collection along two independent tracks, the spoken transcript and sampled frames, then retrieve across both and return a playable, timestamped moment with the evidence that supports it.
Initial scope
Blender open movies under Creative Commons Attribution, one language, a collection starting at roughly two to five hours. Audio extraction and timestamped transcription, timestamped frame sampling, keyword and semantic transcript retrieval, image-text embedding retrieval over frames, combined retrieval, and playable results with supporting transcript excerpts or frames.
Example queries
Find the moment where the presenter demonstrates the dashboard, rather than just mentioning it.
Find a nighttime crowd scene with no visible presenter.

Research question

Open, not answered

When does combining visual evidence with transcript retrieval improve video search, and what are the quality, latency and cost trade-offs?

To investigate

  • Whether adding visual retrieval improves recall over transcript retrieval alone, and on which query types.
  • What frame-sampling density is enough before extra frames stop paying for themselves.
  • What combining the two tracks costs in query latency and indexing time.
  • How the system should behave when nothing in the library actually answers the query.

Already established

  • Nothing yet. No result on this page has been measured.

A text-only reranker reads the transcript, not the picture. It cannot confirm that something appears on screen, and this project will not claim that it can.

Proposed architecture

Design, not built

scenesearch / proposed flow
Stage 1
Video ingestion
Owned or licensed source files, with provenance and permissions recorded per video.
↓
Stage 2
Transcription and frame sampling
Audio extracted and transcribed with timestamps; frames sampled at a chosen density, each keeping its timecode.
↓
Stage 3
Text and visual embeddings
Transcript segments embedded for semantic search; frames embedded in a shared image-text space.
↓
Stage 4
Persistent indexes and metadata
Vector indexes plus a metadata store holding timecodes, source video and provenance.
↓
Stage 5
Candidate retrieval and optional reranking
Retrieve candidates from each track, combine them, and rerank only where a baseline shows it is justified.
↓
Stage 6
Timestamped playback with evidence
A result plays at its timecode and shows the transcript excerpt or frame that produced it.
Cross-cutting
Evaluation
A fixed query set and scoring harness that any configuration can be run against.
Cross-cutting
Profiling
Latency, indexing time, memory and storage measured per configuration rather than estimated.

Evaluation design

  • Begin with 50 to 75 manually reviewed queries, expanding toward roughly 100 to 150 if that proves feasible.
  • Cover spoken-content, visual-only, mixed-evidence, near-match and no-answer queries.
  • Separate development and held-out videos where feasible, and do not tune against held-out results.
  • Report uncertainty and failure modes rather than a single headline number.
  • Do not rely on model-generated ground truth alone; every query in the set is reviewed by hand.

Deliverables, limits and cost

Scope discipline

Engineering deliverables

  • Reproducible ingestion and indexing
  • Search interface and backend
  • Persistent metadata with source provenance
  • Versioned experiment configurations
  • Automated tests
  • Evaluation scripts, and results once they exist
  • Clean-environment setup instructions
  • A performance profile
  • A technical report
  • A short demo
  • Documented limitations

Out of scope for the first release

  • Foundation-model training
  • Autonomous agents
  • Conversational memory
  • Large-scale scraping
  • Searching copyrighted media without permission
  • Kubernetes or comparable infrastructure the project does not need
  • Fine-tuning before a baseline shows the need
  • Enterprise-scale performance claims

Responsible development

  • Owned or appropriately licensed content only.
  • Provenance and permissions recorded per source video.
  • No employer data, code or proprietary workflow.
  • Model and dataset licences checked before use.
  • Minimal collection of personal data.
  • Unsupported claims and retrieval failures written down rather than omitted.
